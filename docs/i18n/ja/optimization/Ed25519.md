# Portable Ed25519 実装記録

この文書は LiberaCrypt の pure-mode Ed25519 実装と、その算術、scalar multiplication、encoding、validation の選択理由を記録します。公開 API は `DigitalSignature.h` から提供され、field、point、scalar helper はすべて内部実装のままです。

## 範囲とエンコーディング

実装は Ed25519ctx や Ed25519ph ではなく RFC 8032 Ed25519 に従います。

- Private key: 32-byte seed。
- Public key: canonical 32-byte compressed Edwards point。
- Signature: canonical 32-byte compressed `R` の後に 32-byte little-endian scalar `S`。
- Hash: Ed25519 で固定された SHA-512。hash selector は受け付けません。

鍵生成は OS entropy boundary から private seed を取得します。与えられた seed と message に対して public derivation と signing は deterministic です。

## Portable field representation

field は `p = 2^255 - 19` です。field element は `uint32_t` に格納した 16 個の little-endian radix-2^16 limb を使います。schoolbook product は 31 個の `uint64_t` coefficient に収まり、各 coefficient は最大 16 個の 16-bit limb 積を加算します。高位 coefficient は `2^256 = 38 (mod p)` の関係で fold し、固定回数の carry pass と mask による conditional subtraction of `p` を行います。

この表現は意図的に次へ依存しません。

- `unsigned __int128` や compiler-specific wide-integer extension;
- architecture-specific intrinsic または assembly;
- variable-length array;
- unaligned または aliasing-sensitive word load;
- native-endian cast;
- signed shift または signed-overflow の仮定。

X25519 backend と同じ portability-oriented radix と reduction identity を使いますが、Ed25519 は独自の Edwards coordinate と strict encoding rule を保持します。

inversion と square-root candidate は固定された公開 exponent を使用します。point decoding は canonical `y < p` のみを受け付け、`x` を復元し、non-square を拒否します。また、復元された `x` が 0 なのに sign bit が 1 である non-canonical encoding も拒否します。

## Extended-coordinate point operation

point は `x = X/Z`、`y = Y/Z`、`T = XY/Z` を満たす extended Edwards coordinate `(X:Y:Z:T)` で表します。addition と doubling は `a = -1` twisted Edwards curve の complete formula を使います。したがって direct affine translation と異なり、scalar multiplication の各 step で inversion を行わず、identity、equal、opposite point に対する exceptional-case branch も不要です。

reference-shaped baseline は scalar bit を一つずつ処理し、各 bit で 1 回の doubling と条件付き addition を行うため最大 256 回の addition が必要です。実装された four-bit window は `0P` から `15P` まで 16 個の multiple を precompute し、64 個の window を処理します。各 window は 4 回の doubling、mask による 16 entry 全走査、zero/leading window を含む 1 回の addition を行います。

その結果、最大 256 回の bit-conditioned addition の代わりに 64 回の window addition と 15 回の precomputation addition を使用します。private operation にとってさらに重要なのは、loop count、point-operation count、table address が scalar digit に依存しないことです。16-entry table は約 4 KiB で、legacy small-stack target でも妥当な範囲に収まるよう意図的に制限されています。より大きな fixed-base table は同一 target の benchmark evidence がある場合にのみ導入すべきです。

これは fixed source-level schedule と説明します。ISO C はすべての compiler と processor で同一の instruction や arithmetic latency を保証できず、この記録は power、EM、speculative、fault、compiler-introduced side channel への耐性を主張しません。

## Scalar arithmetic

SHA-512 出力は `L = 2^252 + 27742317777372353535851937790883648493` に対し、8 個の 32-bit limb を使う fixed-count binary reduction で縮約します。各 input bit ごとに bounded remainder を shift し、mask による conditional subtraction of `L` を行います。

signing equation `S = r + k a (mod L)` は portable 32-by-32-bit schoolbook multiplication により 16 個の 32-bit limb を作り、fixed-count carry propagation と同じ 512-bit reduction を使用します。secret expanded scalar とすべての temporary digest、reduced scalar、point table、coordinate は使用後に明示的に消去します。

## Strict verification ポリシー

verification は signature equation の前に次を確認します。

1. public key と `R` は canonical Edwards encoding であること。
2. `S` は厳密に `L` より小さいこと。
3. public key は identity でないこと。
4. public key に `L` を掛けた結果が identity となり、non-trivial cofactor component を持たないこと。

この prime-order public-key policy のもとで verification は RFC 8032 の直接式 `[S]B = R + [k]A` を検査します。permissive cofactored または ZIP-215 acceptance rule は使用しません。

## 検証根拠

focused test には次が含まれます。

- RFC 8032 の最初の 3 個の pure Ed25519 known-answer vector;
- generated-key public derivation、deterministic repeat signing、empty/non-empty message round trip;
- tampered signature;
- `S = L`、non-canonical public-point と `R` encoding、identity public key;
- invalid identifier、length、null pointer、undersized output、overlapping output/input range;
- conversion と aliasing diagnostic を含む strict GCC C11 warning build;
- AddressSanitizer と UndefinedBehaviorSanitizer;
- 100 個の deterministic seed とさまざまな message を OpenSSL 3.0.13 と双方向で検査し、exact public-key と deterministic signature byte も比較。

OpenSSL は development oracle であり build/runtime dependency ではありません。通常 CI と focused ECC workflow は Ubuntu、macOS、Windows で public test をビルドし、focused workflow は Ubuntu で Ed25519 test を ASan/UBSan でも実行します。

現在 absolute throughput claim は記録していません。window 変更には bit-wise conditional addition に対する明確な operation-count advantage がありますが、timing ratio を公開したりより大きな table を選ぶには再現可能な multi-platform benchmark が必要です。
