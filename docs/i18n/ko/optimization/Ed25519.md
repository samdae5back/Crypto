# Portable Ed25519 구현 기록

이 문서는 LiberaCrypt의 pure-mode Ed25519 구현과 그 산술, scalar multiplication, encoding, validation 선택의 근거를 기록합니다. 공개 API는 `DigitalSignature.h`를 통해 제공되며 field, point, scalar helper는 모두 내부 구현으로 유지됩니다.

## 범위와 인코딩

구현은 Ed25519ctx나 Ed25519ph가 아니라 RFC 8032의 Ed25519를 따릅니다.

- Private key: 32-byte seed.
- Public key: canonical 32-byte compressed Edwards point.
- Signature: canonical 32-byte compressed `R` 뒤에 32-byte little-endian scalar `S`.
- Hash: Ed25519가 고정한 SHA-512. 별도의 hash selector는 받지 않습니다.

키 생성은 운영체제 entropy boundary에서 private seed를 얻습니다. 주어진 seed와 message에 대해 public derivation과 signing은 deterministic합니다.

## Portable field representation

field는 `p = 2^255 - 19`입니다. field element는 `uint32_t`에 저장한 16개의 little-endian radix-2^16 limb를 사용합니다. schoolbook product는 31개의 `uint64_t` coefficient에 들어갑니다. 각 coefficient는 최대 16개의 16-bit limb 곱을 더합니다. 높은 coefficient는 `2^256 = 38 (mod p)` 관계로 접은 뒤 고정 횟수 carry pass와 mask 기반 conditional subtraction of `p`를 수행합니다.

이 표현은 의도적으로 다음에 의존하지 않습니다.

- `unsigned __int128` 및 compiler-specific wide-integer extension;
- architecture-specific intrinsic 또는 assembly;
- variable-length array;
- unaligned 또는 aliasing-sensitive word load;
- native-endian cast;
- signed shift 또는 signed-overflow 가정.

X25519 backend와 같은 portability-oriented radix 및 reduction identity를 사용하지만, Ed25519는 자체 Edwards coordinate와 strict encoding rule을 유지합니다.

inversion과 square-root candidate는 고정된 공개 exponent를 사용합니다. point decoding은 canonical `y < p`만 허용하고 `x`를 복원하며 non-square를 거부합니다. 또한 복원된 `x`가 0인데 sign bit가 1인 non-canonical encoding을 거부합니다.

## Extended-coordinate point operation

point는 `x = X/Z`, `y = Y/Z`, `T = XY/Z`를 만족하는 extended Edwards coordinate `(X:Y:Z:T)`로 표현합니다. addition과 doubling은 `a = -1` twisted Edwards curve의 complete formula를 사용합니다. 따라서 direct affine translation과 달리 scalar multiplication 과정에서 step마다 inversion을 하지 않으며 identity, equal, opposite point에 대한 exceptional-case branch도 필요하지 않습니다.

reference-shaped baseline은 scalar bit를 하나씩 처리하면서 각 bit마다 한 번의 doubling과 조건부 addition을 수행하므로 최대 256번의 addition이 필요합니다. 현재 구현된 four-bit window는 `0P`부터 `15P`까지 16개의 multiple을 precompute하고 64개 window를 처리합니다. 모든 window는 4번 doubling, mask를 이용한 16개 entry 전체 scan, 그리고 zero/leading window를 포함한 1번 addition을 수행합니다.

결과적으로 최대 256개의 bit-conditioned addition 대신 64개의 window addition과 15개의 precomputation addition을 사용합니다. private operation 관점에서 더 중요한 점은 loop count, point-operation count, table address가 scalar digit에 의존하지 않는다는 것입니다. 16-entry table은 약 4 KiB를 차지하며 legacy small-stack target에서도 합리적인 범위에 머물도록 의도적으로 제한했습니다. 더 큰 fixed-base table은 같은 target에서 benchmark evidence가 있을 때만 도입해야 합니다.

이 구현은 fixed source-level schedule이라고 표현합니다. ISO C는 모든 compiler와 processor에서 동일한 instruction 또는 arithmetic latency를 보장할 수 없으며, 이 기록은 power, EM, speculative, fault, compiler-introduced side channel에 대한 저항성을 주장하지 않습니다.

## Scalar arithmetic

SHA-512 출력은 `L = 2^252 + 27742317777372353535851937790883648493`에 대해 8개의 32-bit limb를 사용하는 fixed-count binary reduction으로 감소시킵니다. 각 input bit마다 bounded remainder를 shift하고 mask 기반 conditional subtraction of `L`을 수행합니다.

signing equation `S = r + k a (mod L)`은 portable 32-by-32-bit schoolbook multiplication으로 16개의 32-bit limb를 만들고, fixed-count carry propagation과 동일한 512-bit reduction을 사용합니다. secret expanded scalar와 모든 temporary digest, reduced scalar, point table, coordinate는 사용 후 명시적으로 지웁니다.

## Strict verification 정책

verification은 signature equation을 검사하기 전에 다음을 확인합니다.

1. public key와 `R`은 canonical Edwards encoding이어야 합니다.
2. `S`는 반드시 `L`보다 작아야 합니다.
3. public key는 identity가 아니어야 합니다.
4. public key에 `L`을 곱한 결과가 identity여야 하며, 이를 통해 non-trivial cofactor component가 없음을 확인합니다.

이 prime-order public-key 정책 아래에서 verification은 RFC 8032의 직접 방정식 `[S]B = R + [k]A`를 검사합니다. permissive cofactored 또는 ZIP-215 acceptance rule은 사용하지 않습니다.

## 검증 근거

focused test에는 다음이 포함됩니다.

- RFC 8032의 첫 세 pure Ed25519 known-answer vector;
- generated-key public derivation, deterministic repeat signing, empty/non-empty message round trip;
- tampered signature;
- `S = L`, non-canonical public-point와 `R` encoding, identity public key;
- invalid identifier, length, null pointer, undersized output, overlapping output/input range;
- conversion과 aliasing diagnostic을 포함한 strict GCC C11 warning build;
- AddressSanitizer 및 UndefinedBehaviorSanitizer 실행;
- 100개의 deterministic seed와 다양한 message를 OpenSSL 3.0.13과 양방향으로 검사하고 exact public-key 및 deterministic signature byte까지 비교.

OpenSSL은 development oracle일 뿐 build 또는 runtime dependency가 아닙니다. 일반 CI와 focused ECC workflow는 Ubuntu, macOS, Windows에서 public test를 빌드하며, focused workflow는 Ubuntu에서 Ed25519 test를 ASan/UBSan으로도 실행합니다.

현재 absolute throughput claim은 기록하지 않습니다. window 변경은 bit-wise conditional addition 대비 명확한 operation-count 이점이 있지만, timing ratio를 공개하거나 더 큰 table을 선택하려면 재현 가능한 multi-platform benchmark가 필요합니다.
